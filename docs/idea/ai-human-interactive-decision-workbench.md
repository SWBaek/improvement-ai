# AI–Human Interactive Decision Workbench

## Status

- State: `Parked`
- Last reviewed: 2026-08-07
- Next trigger: 실제 프로젝트에서 채팅 기반 다중 결정 검토의 반복 실패와 Pilot 후보가 확인되면 재개한다.

현재는 의도적으로 탐색을 중단했다. 아직 Capability Blueprint, 실행 가능한 도구, Schema 또는 구현 사양이 아니다.

## 문제

AI가 복잡한 정책, 표준 또는 시스템 구성을 설계하려면 사람이 결정해야 할 항목이 수십 개에서 수백 개까지 늘어날 수 있다. 이를 채팅에서 하나씩 질문하면 다음 문제가 발생한다.

- 사람은 이미 답한 항목과 남은 항목을 파악하기 어렵다.
- 선택지, 장단점과 상호 의존성을 대화 문맥에서 계속 유지해야 한다.
- Yes/No로 답할 수 없는 회사별 규칙과 예외를 체계적으로 입력하기 어렵다.
- 대화가 길어지면 답변의 누락, 오해와 임의 추론 가능성이 커진다.
- 같은 결정을 다시 검토하거나 다른 사람과 공동 검토하기 어렵다.

문서 표준 구조 제정은 대표적인 사례다. Heading 번호와 깊이, 허용 블록, 표·그림·수식·각주, provenance, 검토 상태와 Lint 규칙을 한 번의 대화로 결정하기 어렵다.

## 개념

AI가 결정 공간을 구조화된 질문 카탈로그로 제안하고, 사람이 웹 기반 Workbench에서 선택하거나 직접 서술하며, 그 답변을 다시 구조화된 데이터로 AI에 전달하는 상호작용 방식이다.

```text
AI가 결정 공간과 질문을 구성
          ↓
구조화된 질문 카탈로그
          ↓
HTML Workbench가 입력 화면으로 표현
          ↓
사람이 선택·서술·보류
          ↓
구조화된 답변과 변경 이력
          ↓
AI가 명시적으로 결정된 답변만 사용해 산출물 제안
```

이 패턴의 목적은 AI의 자율성을 확대하는 것이 아니라, 많은 인간 결정을 대화보다 검토하기 쉬운 형태로 바꾸는 것이다.

## 상호작용 모델

### 질문 카탈로그

AI가 각 항목에 다음 정보를 제안한다.

- 안정적인 질문 식별자
- 주제와 질문
- 결정이 필요한 이유
- 적용 범위와 예시
- 가능한 선택지와 각각의 영향
- 권장 선택지와 권장 근거
- 필요한 입력 형식
- 필수 여부와 미결정 허용 여부
- 선행 질문과 조건부 표시 관계
- 자유 입력 또는 예외 설명의 필요 여부

권장값은 기본 확정값이 아니다. 사람이 선택하지 않은 권장값을 AI가 승인된 결정으로 간주해서는 안 된다.

### 지원해야 할 답변 형태

- 단일 선택
- 복수 선택
- 순서 지정
- 숫자 또는 범위
- 짧은 텍스트
- 긴 서술형 텍스트
- 반복 가능한 항목 집합
- 선택 후 예외·조건·근거를 작성하는 보조 필드
- 다른 답변에 따라 나타나는 조건부 질문
- 미결정 또는 보류

Yes/No 질문도 필요한 경우 조건부 허용, 예외와 근거를 서술할 수 있어야 한다. 선택지로 표현할 수 없는 회사 고유 규칙은 사람이 직접 입력할 수 있어야 한다.

### 답변 데이터

질문 정의와 사람의 답변을 분리한다. 답변은 선택한 값뿐 아니라 다음 정보를 유지할 수 있어야 한다.

- 결정, 보류 또는 미결정 상태
- 자유 입력 내용
- 조건과 예외
- 작성자와 변경 시각
- 사용한 질문 카탈로그 revision
- 이전 답변과의 차이

질문이 개정되어도 과거 답변을 조용히 재해석하거나 덮어쓰지 않는다. 호환되지 않는 질문 변경은 사람에게 다시 검토하도록 표시한다.

### 생성되는 산출물

AI는 답변 데이터를 읽고 표준, 정책, Profile, 설정 또는 구현 제안을 생성할 수 있다. 다음 경계를 지켜야 한다.

- 결정된 답변만 확정 규칙으로 사용한다.
- 미결정 항목은 임의로 채우지 않는다.
- 자유 입력을 선택지보다 낮은 우선순위로 취급하지 않는다.
- 답변과 생성된 각 규칙의 대응 관계를 설명할 수 있어야 한다.
- 생성 결과를 적용하거나 외부 시스템에 쓰기 전에 필요한 인간 승인을 받는다.

## Workbench에서 기대하는 경험

- 주제별 탐색과 검색
- 전체 진행률과 미결정 항목 표시
- 선택지별 장단점과 권장 근거 표시
- 서술형 입력과 예외 작성
- 조건부 질문 표시
- 필수 입력과 상호 모순 검증
- 임시 저장
- 답변 가져오기와 내보내기
- 결정 요약과 변경 비교
- 답변 초기화 또는 이전 revision 복원

Workbench는 특정 웹 framework나 배포 방식을 강제하지 않는다. 대상 프로젝트는 정적 HTML, 기존 웹 애플리케이션 또는 다른 UI 환경에 맞게 구현할 수 있다.

## 필수 불변 조건

- 인간이 명시적으로 선택하거나 입력하지 않은 항목을 확정된 결정으로 취급하지 않는다.
- 권장값과 확정값을 구분한다.
- 미결정 상태를 유효한 상태로 보존한다.
- 질문 정의, 사람의 답변과 AI 생성 결과를 서로 분리한다.
- 서술형 답변과 회사별 예외를 손실 없이 보존한다.
- 질문과 답변의 revision을 연결해 나중에 판단 근거를 재현할 수 있게 한다.
- 조건부 질문이 숨겨졌다는 이유로 기존 답변을 자동 삭제하지 않는다.
- AI가 생성한 정책과 설정은 어떤 답변에서 유래했는지 추적할 수 있어야 한다.
- 민감한 답변의 저장 위치와 외부 전송 여부는 대상 프로젝트의 보안 정책을 따른다.

## 적용 가능 사례

- 회사 문서 표준과 작성 Profile 제정
- 프로젝트별 Agent Skill 구성 선택
- 코딩 규칙과 품질 Gate 합의
- 요구사항 또는 검토 체크리스트 설계
- 배포 정책과 환경별 옵션 결정
- 반복되는 아키텍처 선택과 예외 기록
- AI가 생성할 산출물의 범위와 인간 승인 경계 설정

## 위험과 설계 주의점

### 유도 질문

AI가 자신이 선호하는 답을 권장값으로 강조하면 사람의 결정을 왜곡할 수 있다. 선택지마다 영향과 trade-off를 함께 설명하고 직접 입력과 보류를 허용해야 한다.

### 과도한 형식화

초기에 모든 가능성을 완전한 Schema로 만들려 하면 질문 설계 자체가 목적이 될 수 있다. 실제 결정에 필요한 최소 질문 집합부터 시작하고 반복 사용에서 확인된 요구만 확장한다.

### 숨겨진 상호 의존성

개별 답변은 유효해도 조합이 모순될 수 있다. 질문 간 조건과 충돌을 표시하되, 자동 수정하지 않고 사람이 해결하도록 해야 한다.

### 긴 설문 피로

질문을 우선순위와 주제로 나누고 부분 저장과 재개를 지원해야 한다. AI는 이미 결정된 프로젝트 정보를 읽어 중복 질문을 줄이되, 추론한 값은 사람에게 확인 가능한 제안으로만 표시한다.

### 질문 revision과 답변 불일치

질문이 추가되거나 의미가 변경되면 기존 답변을 그대로 새 의미에 적용해서는 안 된다. 영향받은 항목을 식별해 재검토 큐를 만들어야 한다.

## 비목표

- 인간의 정책 결정을 AI가 대신하는 것
- 모든 도메인에 동일한 질문 Schema나 UI를 강제하는 것
- 답변만으로 외부 시스템을 자동 변경하는 것
- 미결정 항목을 AI 권장값으로 조용히 채우는 것
- 이 저장소에서 실행 가능한 questionnaire runtime이나 범용 framework를 배포하는 것

## 유용성 검증 기준

이 개념을 구체적인 Capability로 승격하려면 최소한 다음을 실제 프로젝트에서 확인해야 한다.

- 사람이 긴 채팅 없이 다수의 결정 항목을 검토하고 답할 수 있다.
- 선택형과 서술형 답변을 함께 사용할 수 있다.
- 미결정과 예외가 최종 데이터에서 손실되지 않는다.
- 질문과 답변을 저장하고 다시 불러와 작업을 재개할 수 있다.
- 답변 변경과 그로 인한 생성 결과 변경을 비교할 수 있다.
- AI가 임의 추론 없이 답변에 근거한 산출물을 생성한다.
- 사람의 검토 시간, 누락 또는 재질문이 대화 방식보다 줄어든다.
- 서로 다른 두 종류의 프로젝트에서 프로젝트별 질문과 UI로 적응할 수 있다.
