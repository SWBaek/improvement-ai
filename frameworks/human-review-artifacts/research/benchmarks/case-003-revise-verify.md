# CASE-003 Baseline: 문서 정책 변경과 기준 검증

## 검토 과제

팀의 기술 결정 문서 정책 변경이 이전 피드백을 반영했고 합격 기준을 만족하는지 확인한다.

## 변경 전

중요한 결정을 Markdown 파일에 기록한다. 제목과 설명 형식은 작성자에게 맡기며 변경 이력 규칙은 없다.

## 요청된 변경

- 안정적인 결정 ID를 추가한다.
- 상태와 날짜를 필수로 한다.
- 기존 결정을 덮어쓰지 않고 대체 관계를 기록한다.
- 자동 검증에서 중복 ID와 알 수 없는 대체 대상을 거부한다.

## 변경 후

각 결정은 `DEC-XXX` ID, 상태, 날짜와 결정·이유·결과를 가진다. 기존 결정의 의미를 변경할 때는 `supersedes`에 기존 ID를 기록한다. validator는 중복 ID, 필수 필드 누락과 알 수 없는 `supersedes`를 오류로 처리한다.

## 검증 결과

세 fixture를 실행했다. 정상 결정은 통과했고 중복 ID와 알 수 없는 대체 대상은 각각 실패했다. 필수 날짜 누락 fixture는 아직 작성되지 않았다. 따라서 피드백 반영은 확인할 수 있지만 전체 합격 기준은 아직 충족되지 않았다.

검토자는 변경 반영을 승인하거나 추가 변경을 요청하고, 검증 결론을 승인·거부·challenge할 수 있다.
